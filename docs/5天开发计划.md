# 金融分析报告生成 Agent｜5 天开发计划

> 依据《JiuwenSwarm金融分析报告生成Agent开发实践.md》制定。赛题：【华为openJiuwen】基于 JiuwenSwarm 的 Agent 金融分析报告生成。
> 最终目标：在组委会指定的上市公司池（六大板块）内，由 Agent 自主完成**选股决策 + 仓位配置 + 投资分析报告**，交付 `Portfolio.json` + `个股投资研报/股票代码.md`。

---

## 一、计划概览

### 1.1 总体目标

| 维度 | 目标 |
| --- | --- |
| **核心交付** | 在公司池内选股并输出 `Portfolio.json`（代码: 权重），批量产出 `股票代码.md` 个股报告 |
| **框架要求** | 全部能力封装为 JiuwenSwarm 技能/多智能体团队/Swarmflow 工作流，无独立脚本绕过 |
| **初赛目标** | 投资组合收益率与风险控制指标达标（单标的权重上限、分散度约束生效） |
| **决赛目标** | 报告结构完整、逻辑严谨、数据可溯源 |
| **可复现性** | 决策过程日志 + 资源消耗记录 + 代码与环境说明，第三方可复现 |

### 1.2 总体时间线

| 天数 | 主题 | 核心产出 |
| --- | --- | --- |
| **Day 1** | 技能骨架 + 数据采集层（行情/财报） | SKILL.md、技能目录、QuoteCollector、FilingCollector、公司池加载 |
| **Day 2** | 数据采集完善 + 财务分析引擎 | NewsCollector（迭代式 Deep Research）、RAGRetriever、CodeExecutor、FinanceAnalyzer |
| **Day 3** | 分析引擎完善 + 报告生成层 | Industry/MacroAnalyzer、ChartGenerator、ReportWriter（分治式）、CitationChecker |
| **Day 4** | 多 Agent 编排 + 投资决策 | 五个子 Agent、orchestrator 自检反馈循环、Investor 输出 Portfolio.json |
| **Day 5** | 端到端联调 + 可复现性 + 提交 | Swarmflow 工作流封装、决策日志、自检清单过检、提交材料打包 |

### 1.3 前置准备（Day 1 开工前完成）

- [ ] JiuwenSwarm 环境可启动（模型服务 OpenAI 兼容接口可用）
- [ ] `example/上市公司列表.xlsx` 已解析确认（六大板块约 46 家 A 股）
- [ ] 依赖安装：`pandas numpy matplotlib akshare chromadb sentence-transformers requests beautifulsoup4 ipython`
- [ ] 技能目录创建：`workspace/agent/skills/finance-report/`

## 三、Day 2：新闻采集（Deep Research）与分析引擎核心

### 3.1 目标

完成数据采集层剩余模块，实现 CodeExecutor 与财务分析器，打通"数据 → 分析"链路。

### 3.2 任务分解

| 序号 | 任务 | 对应文档章节 | 预估 |
| --- | --- | --- | --- |
| 1 | 实现 `NewsCollector` 迭代式 Deep Research（初始查询→精炼扩展→信息饱和终止，max_depth=3） | 5.2 | 2h |
| 2 | 实现 `RAGRetriever`（财务方法论知识库构建：分块→向量化→检索） | 5.4 | 2h |
| 3 | 实现混合记忆管理：短期（表头+前后5行压缩）/长期（结论摘要沉淀）/外部（RAG）分流 | 5.5 | 1h |
| 4 | 实现 `CodeExecutor`（IPython 持久化 shell + AST 白名单 + 禁用 exec/eval） | 6.2 | 2h |
| 5 | 实现 `FinanceAnalyzer`（盈利/偿债/成长能力分析 + 估值 PE + 洞察生成） | 6.1 | 1.5h |
| 6 | 打通验证：600519 完成"新闻 Deep Research + 财务分析"，CodeExecutor 内跑通 ROE 计算与画图 | 9.1 | 1.5h |

### 3.3 交付物

- `collectors/news_collector.py`（含 `_initial_queries`/`_refine_queries` 迭代逻辑）
- `collectors/rag_retriever.py` + 初始财务知识库（估值方法、杜邦分析、行业框架文档）
- `analyzers/code_executor.py`、`analyzers/finance_analyzer.py`

### 3.4 验收标准

- [ ] Deep Research 至少执行 2 轮迭代，第二轮查询明显更具体（如"XX 市场份额"）
- [ ] RAG 对"白酒行业估值方法"类 query 返回相关知识片段且带来源
- [ ] CodeExecutor 拒绝 `import os` / `eval()` 等危险代码，放行 pandas/matplotlib
- [ ] FinanceAnalyzer 对 600519 输出毛利率/ROE/增速等指标与 ≥2 条洞察

### 3.5 风险与对策

- **Deep Research 不收敛**：设置 max_depth 与总条数上限双保险，信息饱和判断先用"新增去重条目数 < 阈值"的简单规则
- **知识库冷启动**：先人工沉淀 10-20 篇方法论文档，后续再扩展

### 4.2 任务分解

| 1 | 实现 `IndustryAnalyzer`（景气度 + 竞争格局，竞对直接取同板块公司做两两对比） | 6.3 | 1.5h |
| 2 | 实现 `MacroAnalyzer`（GDP/CPI/PMI 指标 + 政策趋势摘要） | 6.3 | 1h |
| 3 | 实现 `ChartGenerator`（股价走势折线图/盈利趋势柱状图/财务表格，图文同源） | 7.2 | 2h |
| 4 | 实现 `ReportWriter` 分治式生成：先 YAML 大纲 → 逐段生成（每段带前文上下文）→ 图片本地化引用校验 | 7.1/7.3 | 2.5h |
| 5 | 实现 `CitationChecker`（引用率 ≥ 90%、权威来源白名单校验） | 7.4 | 1h |
| 6 | 打通验证：生成 600519 完整报告草稿，按模板含"投资结论与仓位建议"章节，保存为 `600519.md` | 3.3 | 2h |

### 4.3 交付物

- `analyzers/industry_analyzer.py`、`analyzers/macro_analyzer.py`
- `generators/chart_generator.py`、`generators/report_writer.py`、`generators/citation_checker.py`
- `templates/company_report.md` 模板
- 第一份完整个股报告样例（600519.md + 图表）

### 4.4 验收标准

- [ ] 报告结构齐全：核心观点/投资结论/公司概况/行业分析/财务分析/估值/风险提示/数据来源
- [ ] 图表均为本地图片，无失效引用；图表数值与正文一致
- [ ] 引用率 ≥ 90%，来源均命中权威白名单
- [ ] 同板块竞对对比章节自动生成（如茅台 vs 五粮液 vs 汾酒）

### 4.5 风险与对策

- **分段生成衔接生硬**：逐段生成时前文摘要控制在 800 字内，避免噪声；段落间用大纲的 part_desc 做强约束
- **图表中文乱码**：matplotlib 配置 SimHei 字体（CodeExecutor 预配置）

## 五、Day 4：多 Agent 编排与投资决策

### 5.1 目标

五个子 Agent 就位，编排器跑通自检反馈循环，Investor 输出符合提交格式的 `Portfolio.json`。

### 5.2 任务分解

| 序号 | 任务 | 对应文档章节 | 预估 |
| --- | --- | --- | --- |
| 1 | 实现 `PlannerAgent`（研报类型判断、子任务拆解、采集计划）+ `ResearcherAgent`（调度采集层 + RAG） | 4.1 | 2h |
| 2 | 实现 `WriterAgent`/`ReviewerAgent`（对接 Day 3 生成层；Reviewer 四类检查：溯源/图文/结构/合规） | 4.3 | 2h |
| 3 | 实现 `orchestrator.py`（五阶段调度 + max_revision_rounds=2 自检反馈循环） | 4.2 | 1.5h |
| 4 | 实现 `InvestorAgent`：研报结论→投资评分→仓位权重（单标的上限 0.4、分散度 ≥3 只、支持空仓） | 引言/8.2 | 2.5h |
| 5 | Portfolio.json 输出与格式校验（权重之和 ≤ 1.0，代码均在公司池白名单内） | 提交格式 | 0.5h |
| 6 | 打通验证：对 1 个板块（如消费板块 9 家）跑批量流程，产出多份报告 + 组合配置 | 9.1 | 1.5h |

### 5.3 交付物

- `agents/planner.py`、`agents/researcher.py`、`agents/writer.py`、`agents/reviewer.py`、`agents/investor.py`
- `orchestrator.py`（含 ReportRequest/ReportResult 数据类与 portfolio 字段）
- 单板块批量运行样例（9 份报告 + Portfolio.json）

### 5.4 验收标准

- [ ] Reviewer 不通过时可回流重写，≤2 轮后收敛通过
- [ ] 空仓场景：构造全负样本验证空仓输出，且报告含决策逻辑阐明
- [ ] Portfolio.json 通过格式校验：代码在池内、权重合规
- [ ] 批量运行无记忆爆炸（混合记忆分流生效）

### 5.5 风险与对策

- **反馈循环不收敛**：Reviewer 输出结构化 issues 清单，supplement 只补缺口不全量重采；2 轮未过则以当前稿放行并记录
- **评分稳定性差**：Investor 评分用"规则打分（财务/估值/动量）+ LLM 修正"混合模式，固定随机种子

## 七、里程碑与依赖关系

```
Day 1 数据地基 ──→ Day 2 采集+分析 ──→ Day 3 报告生成 ──→ Day 4 编排+决策 ──→ Day 5 联调+提交
    │                   │                    │                    │
    ▼                   ▼                    ▼                    ▼
 公司池+行情财报      Deep Research+         首份完整报告        板块批量运行+
 最小链路通           CodeExecutor 通        600519.md          Portfolio.json
```

| 里程碑 | 时点 | 判定标准 |
| --- | --- | --- |
| M1 数据链路通 | Day 1 结束 | 单标的行情+财报采集成功 |
| M2 分析链路通 | Day 2 结束 | CodeExecutor 内完成财务计算与画图 |
| M3 首份报告 | Day 3 结束 | 600519.md 结构完整、引用率达标 |
| M4 决策闭环 | Day 4 结束 | 单板块批量产出 + Portfolio.json 格式校验通过 |
| M5 可提交 | Day 5 结束 | 自检清单全部过检 |

## 八、总体风险控制

| 风险 | 影响 | 预案 |
| --- | --- | --- |
| 数据源接口变动/限流 | 采集中断 | 采集策略 MCP 封装可替换；本地缓存 + 降级样本数据 |
| 长链路 Token 爆炸 | 批量失败 | 混合记忆分流强制生效；单标的上下文预算控制 |
| 报告质量不稳定 | 决赛失分 | 自检反馈循环 + CitationChecker 双闸门，不达标不放行 |
| 组合回撤大 | 初赛出局 | 权重上限/分散度硬约束；预留空仓开关 |
| 时间不足 | 交付不全 | 优先级：决策闭环（Day4）> 报告质量（Day3）> 批量覆盖（Day5）；保底交付 1 个板块完整产出 |

> **底线原则**：任何一天进度落后，优先保证 Day 4 的"决策闭环"（Portfolio.json 可产出），报告覆盖面可缩减为自选板块子集，但格式与可复现性不可妥协。
