## 二、设计目标

### 2.1 功能目标

| ID | 目标 | 验收 |
|----|------|------|
| F1 | `python run_report.py industry --name 消费板块 --save` 输出**真实**研报 | `reports/finance-report/行业研报/industry_消费板块.md` 字数 ≥ 1500，含 8+ 节，引用率 ≥ 90% |
| F2 | `python run_report.py macro --period 2026Q2 --save` 输出**真实**宏观研报 | `reports/finance-report/宏观研报/macro_2026Q2.md` 字数 ≥ 1500，含 8+ 节，引用率 ≥ 90% |
| F3 | 引用率闸门通过 | Reviewer 不报 `低于 90%` 错误 |
| F4 | 含风险提示 + 免责声明 + 数据来源 | Reviewer 不报章节缺失 |
| F5 | 决策日志含行业/宏观阶段 | `run_stats.json` `phases` 出现「撰写审查:industry/消费板块」「撰写审查:macro/2026Q2」|

### 2.2 非功能目标

- **复用优先**：不改 Planner/Reviewer/Orchestrator 主流程
- **降级兼容**：LLM 不可用时仍可产出结构完整、数据同源的报告（保证 0 调用时也能交差）
- **引用率优先**：每段必带「数据来源：xxx」

### 3.2 数据流（与公司研报对齐）

```
run_report.py industry --name 消费板块 --save
    ↓
orchestrator.generate(
    ReportRequest(report_type="industry", target="消费板块", name="消费板块")
)
    ↓
1. planner.plan(request)
    → plan = {
        report_type: "industry",
        target: "消费板块",
        pool: {消费板块: [(600519, 贵州茅台), ...]},  ★ 新增：注入全池
        collect_tasks: ["news", "rag"],
        analyze_tasks: ["industry", "macro"],
      }
    ↓
2. researcher.research(plan)
    → news_data = collect_news("消费板块")       # 板块级新闻
    → knowledge_chunks = retrieve("消费板块 行业研究框架 竞争格局")
    → finance_analysis = None                    # industry 不跑单标的财务
    → industry_analysis = IndustryAnalyzer.analyze(
        symbol="消费板块",
        pool=plan["pool"],                       # ★ 关键：传入公司池
        news_data=news_data,
        peer_metrics=...                         # 板块内所有标的的财务
      )
    → macro_analysis = MacroAnalyzer.analyze(news_data)
    ↓
3. writer.write(research_data, request)
    → report_writer._write_industry(research_data, request)  ★ 新增
    → 大纲（8 节模板）+ 逐段撰写（LLM 优先 / 模板降级）
    → 图表（板块横向对比柱图）注入
    → 来源清单（含行业分组、宏观指标来源）
    ↓
4. reviewer.review(draft, research_data)
    → 引用率 ≥ 90% 校验、章节完整性、合规校验
    ↓
5. 修订回流 ≤ 2 轮（未通过则重写）
    ↓
6. orchestrator.save_report(result, filename)
    → reports/finance-report/行业研报/industry_消费板块.md
```

宏观研报流程同理，区别在：
- `report_type="macro"`
- `analyze_tasks=["macro"]`（不跑行业分析）
- `name=""` 或 `name="2026Q2宏观经济与 A 股展望"`
- 大纲为宏观专用 8 节模板

### 3.3 模板设计

#### 行业研报大纲（OUTLINE_INDUSTRY_FALLBACK）

| 章节 | 必带数据 |
|------|---------|
| 一、板块核心观点 | 景气等级 + 关键洞察 3-5 条 |
| 二、投资结论与配置建议 | 板块评级（超配/标配/低配）+ 推荐子板块 |
| 三、行业概况 | 板块定义、覆盖范围、代表性公司 |
| 四、宏观环境分析 | GDP/CPI/PMI 传导路径 |
| 五、竞争格局与排名 | 板块内标的横向对比（净利润/毛利率/ROE 排名）|
| 六、估值水平 | 板块平均 PE 区间、分位数 |
| 七、风险提示 | 政策风险、需求风险、估值风险等 3-5 条 |
| 八、数据来源 | 含行业分组来源、宏观数据来源 |

#### 宏观研报大纲（OUTLINE_MACRO_FALLBACK）

| 章节 | 必带数据 |
|------|---------|
| 一、宏观核心观点 | GDP/CPI/PMI 三大指标最新值与趋势 |
| 二、宏观结论与板块配置建议 | 顺周期/逆周期板块建议 |
| 四、通胀与货币环境 | CPI/PPI/M2 |
| 五、增长动能 | GDP/工业增加值/PMI |
| 六、外部环境 | 汇率/外贸 |
| 七、政策与展望 | 货币政策 + 财政政策 |
| 八、风险提示 + 数据来源 | 数据来源清单

（备注：宏观研报章节在模板层允许"二、三"合并为"二、宏观结论"）

### 3.4 降级策略

**核心原则**：即使 LLM 不可用，仍能产出引用率 ≥ 90% 的报告。

```
_write_industry 流程：
1. 大纲（OUTLINE_INDUSTRY_FALLBACK 8 节固定）
2. 逐段撰写：
   ├─ 优先：每段 prompt 含 _materials_for_industry 拼装的 JSON 数据
   ├─ 降级：_template_section 拼接关键数据 + 固定「数据来源：xxx」
3. _assemble_industry：图表（板块横向柱图）+ 来源清单 + 免责声明
```

每段模板段（`_template_section_industry`）**强制段末带「数据来源：xxx」**，确保引用率。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **R1** `industry_analyzer.analyze()` 依赖真实 PE/财务数据，pool 内标的财报未采集 | 行业研报数据空 | 先跑 `research --stage collect` 全池落盘缓存，再跑 industry |
| **R2** LLM 不可用时模板段拼接生硬 | 评分低 | 模板段用程序化语句（"板块整体净利润 X 亿元，同比增长 Y%"），避免 LLM 风格文案 |
| **R3** 引用率闸门 ≤ 90% | Reviewer 报红 | `_template_section` 强制段末带「数据来源：xxx」；模板段来源字典（SECTION_SOURCE_*） |
| **R4** 行业研报无图片 | 影响完整性 | 用 `ChartGenerator` 生成「板块横向对比柱图」（板块内 top 5 标的净利润对比） |
| **R5** 板块名与公司池 key 不一致 | 找不到标的 | 在 `planner.plan(industry)` 时校验板块存在，否则记录 warning |
| **R6** 宏观研报无新闻 anchor | 数据空 | `news_data` 关键词必须命中 GDP/CPI/PMI；MacroAnalyzer 有降级路径 |

## 七、设计决策记录

| 决策点 | 选项 | 选择 | 理由 |
|--------|------|------|------|
| 行业研报板块范围 | 单板块 vs 全行业 | **单板块（指定 --name）** | 跑批可控，时间紧；评测期可对单板块深入分析 |
| 宏观研报周期格式 | Q 季 vs 年 vs 月 | **季度（2026Q2）** | 与财务报告期对齐，最常用 |
| LLM 不可用降级 | 完全空 vs 模板 | **模板降级（每段程序化拼接 + 来源）** | 保证 0 LLM 调用也能交差，引用率合规 |
| 是否复用 `_write_company` | 复用 vs 新写 | **新写 `_write_industry` / `_write_macro`** | 数据结构、章节、图表都不同，复用会引入复杂条件分支 |
| 行业研报图表类型 | 折线/柱状/雷达 | **柱状（板块横向对比）** | 最直观展示排名，渲染稳定 |
| 是否要求 RAG 知识库 | 是 vs 否 | **是（已存在）** | 增加报告方法论参考的「数据来源」|
