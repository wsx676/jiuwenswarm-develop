## 四、关键发现（影响落地决策）

### 4.1 🔴 **最关键的两个 critical（必须改方案）**

| 问题 | 落地影响 |
|------|---------|
| **§4.4 预扫全池翻倍** | 30 标的从秒级恶化到十秒级；且方案误说「缓存命中代价低」（实际仍含 analyze + citations） |
| **缺乏 SentimentScorer Protocol** | 文档「§十 未来要换 LLM」是真目标，但当前设计焊死词表；要么现在就抽象，要么明确接受「不抽象」 |

### 4.2 🟡 **3 个跨维度共识的改进（ROI 高）**

1. **§4.2 词表复用**：删 38 词字面量 → `from industry_analyzer import ...`
2. **§4.4 预扫合并**：删 `_sector_mom20_avg`，并入 `score_pool` 同板块遍历
3. **§四/§五/§六/§七 重叠章节**：合并为单一「自检与验收」章节

### 4.3 🟢 **结构与文档卫生（建议改进）**

- `score_research` 的 `sector_avg_mom20` 应作**第二参数**（避免重算财务/估值/风控）
- records 应一次性算好挂到 `research_data["momentum_factors"]`（避免 5+ 次重复遍历）
- 配置化权重 `investor_cfg.get("weights")` 不存在，需先在 `__init__` 加 `self.weights = ...`
- §六风险表补「R7 性能」项，§七验收补「全池 < N 秒」「单次 _momentum_score < 1ms」
- 文档引入 LLM 调用频次显式声明（不引入新 LLM 调用）
